# 即时拨测浏览器请求生命周期

日期：2026-10-10，前端基线 `d1bb6f8`，后端配套基线 `d7fd6fd`。本批只改前端运行代码，不改权限、拨测指标语义、定时规则或模型调用。

## 已确认的问题

- 通用 POST 封装丢弃 options，页面没有请求生命周期控制。离开即时拨测页后，请求仍可能继续执行；协议切换缺少旧结果隔离。
- API helper 自行显示成功提示，并将失败对象作为正常返回值；页面未检查业务 code 和有效指标。空数组可以成为空结果表，旧请求可能产生迟到反馈。
- 提交绕过表单校验，反复点击没有同步防重入；请求头、正文及结果被调试日志输出。
- 加载遮罩覆盖整个页面，协议切换无法直接用于结束当前拨测。

## 修复

1. 通用 POST 仅新增可选 AbortSignal，不改认证、租户、正文和响应处理。即时拨测 helper 直接传递结果/异常，不自行提示成功。
2. 页面每次请求持有独立 AbortController 和身份引用；卸载、协议切换、输入变化时取消并清理旧结果。所有状态更新和完成提示都要求仍是当前请求；旧请求 finally 不能清掉新请求的 loading。
3. 校验前同步防重入；等待中禁用提交。协议标签保留可点击，表单区域仍显示拨测中。取消不显示失败或成功，真实错误就地展示并允许重试。
4. HTTP 成功码和业务 code 均不代替结果检查：要求存在对应协议的有限数值主指标。空结果是错误；目标不可达的有效指标仍显示“拨测完成”，表内保留失败状态，不能将完成理解为目标健康。
5. 提交执行原有表单约束，超时/ICMP 数量和间隔限制为正整数。基本端点检查保留内网主机名、HTTP query 和 IPv6；不是 DNS 验证，也不替代后端访问控制。数值使用 Number，与校验一致，避免科学计数法被 parseInt 截断。高级选项未打开时仍使用原默认值。
6. 删除本页完整表单、请求、响应和异常对象调试输出，避免请求头或正文出现在控制台。

## 验证记录

- 44 项单元测试、TypeScript 检查及生产构建通过。新增六项 API/公共 POST 测试覆盖 signal 转发、旧调用方式和异常传播。
- 五项浏览器专项连续三轮、15 项通过：真实 XHR 取消、SPA 卸载、双击防重入、旧响应隔离、两类错误 code/空结果、失败指标与重试、表单校验及敏感参数不落日志、四协议内网/IPv6/科学计数法兼容。
- 保持最终生产构建不变，全站浏览器回归 325 项通过、2 项按需容量测试未启用。桌面 1440px、手机 390px 结果页截图已人工检查，未见页面横向溢出；这不等于所有浏览器及真实网络环境验收。

用例使用本地生产构建、本机 Chrome、隔离 API fixture，覆盖桌面和手机；不访问真实拨测目标，不产生生产网络探测。测试直接监听浏览器 XHR abort，离开页面使用 SPA 导航，不以整页刷新带来的浏览器自动取消代替页面 cleanup 验证。延迟旧响应在新响应后释放，验证结果隔离和无迟到反馈。

## 发布与边界

- 只需前端新镜像；后端仅同步维护文档，Agent 不变，无存储迁移或新增依赖。未部署生产。
- 后端取消支持已在前三批加入。浏览器实际 abort 与后端本地 context 测试分别有证据，但真实 Ingress 转发断连、Linux ICMP 和生产容量尚未联合验收。
- 取消不能撤销对端已接收的 HTTP POST 等副作用；不新增自动重试。
- 本批不声称减少固定百分比 CPU/内存、降低生产 p95 或完成总体性能优化。整体等待 Redis 在途取消方案和真实数据库/容器容量验收。
