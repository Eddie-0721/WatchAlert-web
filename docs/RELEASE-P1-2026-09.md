# P1：告警处置上下文与安全预览

日期：2026-09-07。配套前后端均为 eddie，Agent 位于后端仓库 agent-service/。

## 本批交付

- 告警 URL 保存队列、环境、服务、中心、严重度、搜索与分页；可分享链接。当前详情通过事件指纹恢复（事件仍需存在于查询结果）。
- 按租户/URL 在浏览器会话内保存滚动位置。进入 Copilot 后可返回原筛选、页码和详情；恢复懒加载页面时等待内容高度，不重置横向布局。
- 同一查询刷新时保留列表并标明最后更新时间；切换查询不显示上一组结果。没有自动轮询或“新告警数量”功能。
- 静默优先预填实际资源条件；缺少资源 Label 时提示服务级范围。原因须用户填写；只打开一个任务抽屉。
- 新增静默影响预览：当前匹配总数、前 5 个样例、中心、条件、时间和原因。修改表单立即使预览失效；保存时重新核对条件、原配置与匹配指纹集合，预览 5 分钟有效。
- 预览是当前非恢复事件快照，不是未来通知数或最终影响上限；未来新增匹配事件也会静默。0 条匹配仍可以创建未来维护窗口。
- 保存成功留在结果状态，展示静默 ID，允许返回现场；失败保留表单，不通过旧接口绕过预览。保存不等于已发生通知抑制，实际生效依赖正常运行的缓存和调度。
- Copilot 带入当前事件和 30 分钟/1 小时/6 小时分析窗口，发送时固定 Unix 时间；实际查询时间以工具证据为准。恢复历史会话清除新带入的告警线索，避免串场。
- Copilot 与系统设置提供手动连接诊断。设置页诊断使用服务端已保存配置，不会保存表单或测试未保存的 Key。
- Manage → 规则维护交互预览：独立示例流程，包含查找、草稿编辑、演示测试、差异核对。不是新的正式规则编辑器；不执行 PromQL，不写真实规则，演示草稿只在页面内存中保留。

视觉沿用根目录 DESIGN.md / WATCHALERT-DESIGN.md：简洁表格与任务流，状态保持语义色，移动端底部动作留出导航安全区。

## 新接口与权限

| 接口 | 权限项 | 用途 |
| --- | --- | --- |
| POST /api/w8t/silence/silencePreview | silencePreview | 静默范围预览，返回当前匹配样例 |
| POST /api/w8t/agent/diagnostics | agentDiagnostics | 当前用户能力、Agent / 网关 / 模型连接诊断 |

已有非管理员角色不会自动获得新权限。管理员应在角色管理中按需要授予；silencePreview 可读取当前租户匹配事件摘要，只授予应当看到这些告警的人员。创建/编辑仍需原有 silenceCreate / silenceUpdate 权限。Agent 工具继续使用当前用户业务权限、工具白名单、环境/数据源限制和人工确认，不因新增诊断放宽写权限。

后端内部新增 POST /v1/diagnostics（Agent）与 GET /api/w8t/internal/agent/health（Go），都要求服务 Token。诊断只检查连接及 DeepSeek 的 GET /models，不发送聊天生成请求，不执行 Prometheus 或业务写 Tool。探测不跟随重定向，限制超时与响应大小，前端只收到固定检查代码，不返回原始凭据或远端错误正文。

“模型检查通过”仅表示当前凭据能读取模型列表且列表含所选模型，不证明余额、推理或所有 Tool 可用。环境变量方式的模型保留回退，但不自动向未知供应商转发密钥探测，显示未探测。真实 Prometheus 可用性由实际授权查询验证。

## 兼容性与部署

1. 保留原三组件镜像 tag，备份数据库和配置，先在测试环境升级。
2. 先部署 Go 后端和 Agent，再部署前端；Agent 需从同一后端提交的 agent-service/ 构建。旧 Agent 缺少诊断接口会显示不可用，不是假成功。
3. 本批无数据库新列。静默新增/更新响应返回保存对象；请求新增 previewHash / previewAt。
4. 旧 API 客户端可省略两项预览字段继续调用，但必须满足新的基本校验：名称、原因、故障中心、1–50 个有效条件、有效起止时间及最长 30 天。新页面与新 Agent 提案携带预览校验。摘要是新鲜度检查，不是签名授权凭证，也不是数据库/缓存跨系统事务锁。
5. 空条件、错误正则、缺失或非字符串 Label 不再可能扩大匹配范围。等值/不等值/正则规则与实际通知抑制复用同一函数。正则沿用既有 Go 匹配语义，不强制自动锚定。
6. 修复未来开始的静默状态赋值、SQL 更新忽略 status=0 的问题；通知匹配增加实际起止时间检查。数据库保存失败不先写静默缓存。
7. 内部健康接口应只在服务网络使用；沿用既有 Agent Token、Credential Key，不能将密钥写入 URL 或前端。诊断时仍需要 Agent 容器能访问模型 API。

不改变国内 npm / pip 镜像配置。镜像命名继续用 harbor.guardforceai.cn/other/watchalert-web，后端及 Agent 沿用已有名称并使用唯一 tag。本机没有 Docker，因此未进行实际镜像构建和生产部署。

## 验证与边界

- 前端单元测试覆盖 URL 归一化、跨租户安全返回及既有范围/流解析；浏览器隔离 API 测试覆盖桌面/390px、返回现场、静默预览失效、服务端拒绝、保存结果、诊断降级与演示页无写操作。
- Go 专项测试覆盖共享匹配器、租户隔离、预览时效、匹配/原配置变化、拒绝写入及诊断响应白名单；Python 测试用 MockTransport 验证只请求模型列表、网关认证及不泄露错误内容。
- 后端仓库既有 notice/probing 等包仍有 vet 格式字符串问题。新增仓储回归单独使用 go test -vet=off ./internal/repo -run '^TestSilenceUpdatePersistsFutureStatusAndLabels$'，其余主专项测试保留 vet；不宣称全量 go test ./... 通过。
- 未访问生产告警，未调用真实 DeepSeek 推理或真实 Prometheus。截图使用隔离测试数据，位于本地 test-results/visual/。
- 还未建设：独立故障记录、自动根因聚合、规则评估遥测、完整规则测试/发布流程、对象级权限重构、外部系统 Connector、全量页面 TypeScript 改写。现有故障中心仍是通知与路由配置，不冒充 Incident 系统。

上线建议先验收一个测试环境的单资源静默、一次已授权 Prometheus 查询及角色权限错误反馈，再向生产推广。不得通过放宽生产写权限来解决配置或连接错误。
