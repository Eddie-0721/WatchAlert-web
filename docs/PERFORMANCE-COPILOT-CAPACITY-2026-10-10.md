# Copilot 容量基线与流式 Markdown 节点复用

日期：2026-10-10。前端基线 `91741b7`；本批后端仅维护记录、独立 Agent 未改。

## 测量方法与限制

新增按需运行的 `tests/ui/copilot-capacity.spec.mjs`，使用本地 Chrome、生产构建、固定合成消息和模拟 API，不访问真实模型/生产服务：

- 50/250/1000 条历史按真实“每次加载 50 条”逐批前插，包含用户文本、Markdown 标题/列表/YAML 代码和折叠证据，不直接绕过分页塞入 1000 条。
- 单条消息使用约 8/32/64 KiB 的完整 Markdown 片段，无故意破损语法；这些不是实际生产消息分布。
- 堆数据为主动 GC 后的浏览器 `JSHeapUsedSize`，不是进程 RSS/整机内存；节点为 CDP DOM 计数，包含页面外壳，不是只计消息。
- 时间为 renderer `TaskDuration` 的增量，不是网络等待时间、生产 p95 或端到端响应 SLO。输入数字为输入 payment 的七个字符合计，不是每键时间。
- **关闭 Playwright trace 的整页快照，并在测量区间外查找/聚焦控件**。初版混入测试快照与定位工作，1000 条输入曾显示约 160–180ms；该口径弃用，不能作为应用缺陷或优化收益。禁用快照后的 DOM/堆也更接近应用自身。
- 不设依赖本机速度的 CI 毫秒阈值；默认跳过容量测量，仅显式启用。运行会输出 JSON，并附入 Playwright 附件，便于同机同版本比较。

## 已修复的实证问题

共享 `MarkdownRenderer` 每次渲染都创建新的 h1–h6/p/code 组件函数；流式追加尾部文字时，已经完成的标题、段落和代码节点也被卸载重建。旧构建的新增浏览器用例记录这三类 DOM 元素，第一次追加后 `isConnected` 全为 false，明确复现。

将组件映射移至模块级并 memo 代码高亮组件。未变化的代码字符串/语言复用高亮；变化中的代码仍正确更新。现有字体、边距、颜色、语言清单、空状态和换行预处理不变，不增加依赖。

回归同时验证：未闭合代码块继续生成后显示新增字段；完成代码块后的三次文字追加与最终回复保留原 DOM 节点。此修复避免无意义的重建，但 Markdown 文档本身在内容变化时仍需解析，不能声称整个流式解析已增量化。

## 复现命令（PowerShell）

```powershell
npm run build
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
$env:WATCHALERT_CAPACITY_TEST = '1'
npx playwright test tests/ui/copilot-capacity.spec.mjs --repeat-each=3
Remove-Item Env:WATCHALERT_CAPACITY_TEST
```

Chrome 路径根据本机调整；安装了 Playwright Chromium 时可不设置可执行路径。Playwright 自动启动本地预览；不能与同一构建目录的重建同时进行。
