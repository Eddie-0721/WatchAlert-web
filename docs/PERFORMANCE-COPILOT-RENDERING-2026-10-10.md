# Copilot 历史消息与证据渲染优化

日期：2026-10-10；前端基线 `b682620`。仅前端运行代码变更，后端只更新维护记录，独立 Agent 无变更。

## 问题与复现

`Copilot` 的输入、运行状态和流式文本更新都重新遍历消息，重复过滤证据并调用 `evidenceView`；即使证据折叠，该函数仍提前格式化 source/query。Markdown 本身已有 memo，不能因此认定整条消息也已隔离。

使用真实 Chrome、本地生产构建、50 条模拟历史消息，每条有一份带识别标记的 source。在浏览器中计数这些 source 的 `JSON.stringify`，不统计网络外层封装或其他对象：

| 场景 | 修改前 | 修改后 |
|---|---:|---:|
| 恢复 50 条消息，未展开任何证据 | 50 次 | 0 次 |
| 展开一条证据后连续输入 payment | 额外 350 次 | 0 次 |
| 修改后首次展开一条证据 | — | 仅格式化这一条 |

输入测试在 1440px/390px 均覆盖。数字是固定场景下的格式化调用数，不是整页渲染次数、CPU 降幅或生产响应时间。修改前构建上新增三个回归均失败，未用推测替代复现。

## 实现范围

- 会话列表和单条消息分别用现有 React memo 复用；保持稳定的确认回调。输入不再重建消息子树，流式更新只改变正在生成的消息对象。
- 证据解析按该消息证据引用复用；证据体变成组件，由现有 Collapse 首次展开时挂载，不提前执行 JSON 格式化。已展开状态随稳定消息 ID 保留，加载更早消息不重置阅读中的面板。
- 执行结果只替换引用该 actionId 的消息与证据；相同操作在多个消息中的记录都更新，其余消息/证据引用保留。
- 权限/运行状态仍作为显式参数传入。无写权限、运行中等情况下确认按钮保持禁用；后端非 executed 结果不更新成已执行；仍必须打开确认弹窗并由用户点击执行。没有自动确认、自动重试或绕过后端校验。
- 无新依赖、页面样式或布局改动，无历史截断，也未引入全局证据缓存。

## 验证

- 31 项单元测试、类型检查、生产构建通过；新增纯函数测试覆盖缺失/非法证据、无匹配时保留数组引用、多消息同操作更新与不修改原对象。
- 6 项新增浏览器用例连续三轮、共 18 项通过：证据按需生成、桌面/手机输入、前插至 100 条消息、持续流式更新、展开状态、无权限、显式确认、后端未确认结果、成功后状态更新及停止后恢复按钮。
- 最终构建保持不变，全部 304 项浏览器回归通过，包括新增专项、凭据表单、全站挂载、关键流程和已有性能用例。挂载检查不等于所有页面所有业务路径的验收。
- 写接口和模型流均为模拟。后端未确认后的第二次请求由测试再次点击确认触发，不是应用自动重试。
- 未做生产压测或调用真实模型。入口/编辑器已有大块构建提示仍存在。

## 发布与剩余边界

合入前端 eddie 后，仅需重建前端镜像，可以单独回滚，无数据/配置迁移。本批未部署生产。

已加载的消息和首次展开后的证据仍保留 DOM；无限手动加载/连续发送不会因此变成固定内存。首次解析大型单条消息、初次 Markdown 渲染、长回复持续 Markdown 解析仍有开销。运行开始/结束或权限变化时，相关按钮必须重新渲染，不能为降低计数而省略状态更新。下一步需结合规模测量处理剩余长文本/DOM 与资源预算，不直接引入虚拟化或无声截断。

全系统的 Redis 网络取消、普通告警全量扫描、真实 SQL 索引和生产容量验收继续保留；本批不是整体性能目标完成。
